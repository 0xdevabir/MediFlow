# T00 — Foundation & shared contracts: report

Status: done. `./mvnw -q verify` green (31 tests: 6 unit, 25 integration).

## What was built
- **Maven** (`backend/pom.xml`): Java 21, Spring Boot 3.4.5, every dependency listed in the task; failsafe runs `*IT` during `verify`; Testcontainers pinned to 1.21.4.
- **Infra**: `infra/docker-compose.yml` (postgres:16, redis:7, rabbitmq:3-management, minio, mailpit), `.env.example`, `.gitignore`, `README.md`, `ai-service/README.md` stub.
- **Schema** `V1__baseline.sql`: every table in the task list. `audit_event` is append-only: a trigger rejects UPDATE/DELETE (per row) and TRUNCATE (per statement), and UPDATE/DELETE/TRUNCATE are revoked from role `mediflow` when that role exists. Seeds `system_setting ai.confidence.threshold = 0.85`.
- **Domain**: one JPA entity per table in `com.mediflow.shared.domain` (all extend `BaseEntity`: UUID `id`, `createdAt`, `updatedAt`, `@Version version`), one Spring Data repo per entity in `shared.repo`, shared enums.
- **Encryption**: `AesGcmAttributeConverter` (AES-256-GCM, random 12-byte IV, stored as Base64(iv‖ct‖tag)) on `Patient` nationalId/phone/email. Key comes from `MEDIFLOW_FIELD_ENCRYPTION_KEY`. Startup fails if the key is missing (outside the `dev`/`test` profiles) or doesn't decode to 32 bytes.
- **Events**: records nested in `com.mediflow.shared.event.DomainEvents`.
- **Ports** in `shared.port`, with fallback beans in `shared.port.stub.LoggingPortStubs`.
- **Security** (`config.SecurityConfig`): form login at `/login`, deny by default, CSRF (cookie repo), CSP / HSTS / frame DENY / referrer policy, 15-minute session, HttpOnly + SameSite=Strict cookie, `@EnableMethodSecurity`, BCrypt. `MediflowUserDetailsService` reads `app_user` + `user_role`. `DevDataLoader` (profile `dev` only) seeds one user per role.
- **Web**: `templates/layout/base.html` provides these fragments:
  - `head(pageTitleKey)`
  - `nav`: role-aware via `sec:authorize`, with an EN/বাংলা switcher using `?lang=`
  - `flash`
  - `scripts`: Bootstrap bundle + `static/js/sse.js` → `MediFlowSSE.subscribe(url, {onMessage,onError})`

  Also built: `login.html`, `home.html`, `coming-soon.html`, error pages `error/{403,404,4xx,500}.html`, `PlaceholderController` for all 10 module roots, `GlobalExceptionHandler`, `CurrentUser`, cookie `LocaleResolver` (`MEDIFLOW_LANG`), and a `MessageSource` over all 13 `messages/<module>_{en,bn}` bundles.
- **Tests**:
  - `MediflowApplicationIT`: context loads, Flyway V1 applied, audit_event UPDATE/DELETE/TRUNCATE rejected.
  - `LoginAndNavigationIT` (MockMvc, real dev seed):
    - all 9 seeded users can log in; a wrong password is rejected

    - the 10 placeholder pages render

  - `AesGcmAttributeConverterTest`: round-trip, random IV, tamper detected, null-safe.

## Contracts Wave-1 agents must know
- **Entity names that differ from table names:**
  - `PractitionerRoleEntity` (table `practitioner_role`)
  - `ConditionDx` (`condition_dx`)
  - `QueueEntry`
  - `VitalObservation`
  - `AppUser`, whose roles are `Set<Role>` in an element collection on `user_role`

  Repos follow `<Entity>Repository` (e.g. `PractitionerRoleEntityRepository`).
- **Roles**: `shared.domain.Role` enum constants are the authority strings themselves (`ROLE_DOCTOR`, …). Use `hasRole('DOCTOR')` in `@PreAuthorize` / `sec:authorize`.
- **Events**: `com.mediflow.shared.event.DomainEvents.<Name>`, e.g. `DomainEvents.PrescriptionSigned(prescriptionId, patientId, signedBy, at)`. Others:
  - `VitalsClassified(encounterId, patientId, VitalClass patientLevel, at)`
  - `RedAlertRaised(redAlertId, patientId, hospitalId, TriageLevel level, at)`
  - `LabOrderCreated(labOrderId, patientId, hospitalId, String orderType, at)`
  - `LabReportVerified(reportId, labOrderId, patientId, abnormal, critical, at)`
  - `AiJobCompleted(jobId, encounterId, String status, at)` / `AiJobFailed(jobId, encounterId, String reason, at)`
- **Ports**:
  - `AuditPort.record(UUID actorUserId, UUID patientId, String action, String resourceType, UUID resourceId, Map<String,Object> details)`
  - `NotificationPort.notifyUser(UUID userId, channel, locale, subject, body)` / `notifyPatient(UUID patientId, …)`
  - `PatientAccessPort.isAssigned(UUID doctorId, UUID patientId)`: the stub returns **false** (deny by default)
  - `ObjectStoragePort.put(key, InputStream, length, contentType)` / `get(key) → Optional<InputStream>` / `delete(key)`: the stub is in-memory
  - `ClockPort.now()`

  To replace a stub, declare a `@Component` implementing the port. The stubs are an auto-configuration, so they back off reliably.
- **`CurrentUser`** (bean `currentUser`) provides:
  - `username()`
  - `userId()` and `requireUserId()`: the `app_user.id`, to use as the AuditPort actor
  - `appUser()`
  - `hasRole("DOCTOR")`
- **Flash**: add a redirect attribute `successKey`/`errorKey` (a message key) or `successMessage`/`errorMessage` (already-resolved text), then include `~{layout/base :: flash}`.
- **Page skeleton**: copy `templates/coming-soon.html`.
- **Tests**: name integration tests `*IT` and extend `com.mediflow.support.AbstractIntegrationTest`. Add `@ActiveProfiles({"test","dev"})` to get the seeded users (`<role>`/`password`; usernames are `patient, doctor, nurse, frontdesk, labtech, pharmacist, er, admin, approver`).
  - The `test` profile (`src/test/resources/application-test.yml`) **disables Redis, Spring Session, RabbitMQ and mail**. T06/T09/T10 tests that need Rabbit must start a `RabbitMQContainer` and override `spring.autoconfigure.exclude` (e.g. their own profile).

## Deviations
- **Vitals**: stored in a single `vital_observation` table (`vital_type`, `value_numeric`, `value_text`, `unit`, `classification`), not as JPA inheritance. T05 can model `NumericVital`/`BloodPressureVital` in its domain layer (e.g. BP as `value_text` "120/80", or extra columns in V300+).
- **Testcontainers**: bumped to 1.21.4. The Boot-managed 1.20.6 can't talk to Docker Engine 29 (API 1.32 is below its minimum of 1.40).
- **Test profile location**: `application-test.yml` lives in test resources, so it isn't packaged in the jar.
- **TRUNCATE**: also blocked on `audit_event`, which the task didn't ask for.
- **Message basenames**: listed both in `spring.messages.basename` and in the `WebConfig` `MessageSource` bean. The bean wins; they are kept identical.

## Open issues
- The `dev` profile (Redis session + RabbitMQ) wasn't smoke-run against `docker compose up`. Ports 5432/6379/1025 on this machine are taken by other projects. Boot + login are covered by the MockMvc IT under the `test` profile. Before running, change the ports in `.env`.
- `minio/minio:latest` and `axllent/mailpit:latest` aren't pinned. T13 should pin them.
- The CSRF token repo is the cookie variant (`withHttpOnlyFalse`), so JS can read it for future fetch/SSE POSTs. T01 may tighten this.

## How to run
```bash
cp .env.example .env            # adjust ports if busy
docker compose -f infra/docker-compose.yml --env-file .env up -d
cd backend
export JAVA_HOME=/opt/homebrew/opt/openjdk@21 PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev     # http://localhost:8080, e.g. doctor / password
./mvnw verify                                             # needs Docker
```
