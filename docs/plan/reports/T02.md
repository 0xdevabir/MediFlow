# T02 — Patient registration & profile (M1): report

Status: code complete on `feat/T02-patient`. **Tests were not run** (coordinator rule: no `mvnw verify` / test, no Docker). `./mvnw -q -DskipTests test-compile` is green.

## What was built

All under `com.mediflow.patient/**`, `templates/patient/**`, `messages/patient_{en,bn}.properties`, Flyway `V150__patient_module.sql`.

### Schema (V150)
- `allergy`: `verified`, `source`, `reported_by`, `verified_by`, `verified_at` (self-reported default unverified)
- `patient_profile`: registration source, blind indexes (`national_id_hash`, `identity_hash`), phone/email verified timestamps
- `patient_mrn_counter`, `patient_contact_verification`, `patient_history_item`, `patient_demographic_change`, `patient_document`

### Services
- **PatientRegistrationService** — self sign-up (AppUser + Patient + ROLE_PATIENT) and front-desk walk-in (demographics only); consent via local `PatientConsentGateway`; OTP issue; publishes `DomainEvents.PatientRegistered`; duplicate detection on national ID **or** name+DOB+phone via HMAC blind indexes
- **MrnGenerator** — `MF-YYYY-NNNNNN` (Asia/Dhaka year), atomic upsert counter
- **PatientProfileService** — read/search, **contact-only** update (clears verification + re-issues OTP), demographic change request/review, QR card token
- **ContactVerificationService** / **OtpIssuer** — 6-digit OTP, 10 min TTL, 5 attempts, 60 s cooldown, hash-at-rest, via `NotificationPort`
- **PatientClinicalHistoryService** — self-reported allergies/history (`verified=false`); `confirmAllergy` / `confirmHistory` for T05
- **PatientIdentityService.verify(mrnOrNationalId, dob)** — two-identifier match (R5)
- **PatientDocumentService** — ID scan upload to `ObjectStoragePort` (≤5 MB; JPEG/PNG/WebP/PDF)
- **QrTokenService** — signed short-lived token + PNG data URI (zxing)
- **PatientAccessGuard** (`@patientAccess`) — object-level checks aligned with §12 / Table 17
- **PatientAudit** — wraps `AuditPort` on every read/write

### Web
- Public `GET/POST /patients/register` (`PatientPublicSecurityConfig` `@Order(1)`)
- Front desk: `/patients/walk-in`, `/patients/search`, `/patients/changes`
- Profile: `/patients/{id}`, `/patients/me`, card, contact, OTP, allergies, history, documents
- Templates + EN/BN message bundles

### Tests (written; not executed)

## Deviations
1. **No `GET /patients` mapping** — would collide with T00 `PlaceholderController`. Landing is `/patients/search` (staff) and `/patients/me` (patient). Request in `docs/plan/requests/T02.md`.
2. **Consent** — T01 not on this branch; `PatientConsentGateway` + `RepositoryPatientConsentGateway` write shared `consent` (TERMS + DATA_PROCESSING, `REGISTRATION/v1`).
3. **Walk-in** creates no portal `AppUser` (demographics only); self sign-up creates the account.
4. **`PatientAllergy`** entity maps `allergy` alongside shared `Allergy` (extra verification columns); rows from other modules stay unverified by DB default.
5. **Password policy** — local minimum 12 characters (T01 `PasswordPolicy` not available cross-module).
6. **Nav `/patients`** still hits placeholder until T00 removes it.
