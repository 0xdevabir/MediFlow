# T05: Consultation & vitals classification (M3): report

Status: code complete on `feat/T05-consultation-vitals`. **No tests were run for the final state.** Per the coordinator's instruction, `./mvnw verify` was skipped and Docker was never started. `./mvnw -q -DskipTests test-compile` is green.

## What was built (all under `com.mediflow.clinical`)

### Vitals (polymorphic classifier)
- `VitalSign` + `NumericVital` + `BloodPressureVital` with `parse` / `classify` against a shared `VitalRuleSet`.
- Half-open adult rule encoding of R&D v1.3 §11 (HR/RR/TEMP/SpO2/BP components/MAP/shock index) in `V301__clinical_vital_rules_seed.sql`, mirrored by `AdultDefaultRules` for unit tests.
- Derived: MAP = (SBP + 2·DBP)/3, shock index = HR/SBP, pulse pressure informational only; patient level = max of all readings.
- Data-driven types via `clinical_vital_definition` (`VitalCatalogService`); rule-only glucose proven in `VitalSetClassifierTest`.
- `VitalRuleCache`: Redis when available, in-process fallback when Redis is excluded (test profile); `evict()` for T11.
- Nurse entry UI at `/clinical/vitals/entry/{encounterId}` with preview colour coding; persists entered rows to `vital_observation` (UCUM + LOINC on the definition); publishes `DomainEvents.VitalsClassified`.
- Trend view `/clinical/vitals/trend/{patientId}` using inline SVG (`TrendSvg`), not Chart.js (pom is out of scope).

### Consultation
- Encounter open from checked-in appointment; consultation page with allergies (+ confirm via `clinical_allergy_confirm`), active signed meds, vitals trend snippets, verified lab reports, ICD-10 search (`/clinical/api/icd10`), versioned notes, patient-readable summary.
- "Order lab test" → local `LabOrderPort` / `NoOpLabOrderPort` publishes `LabOrderRequested` (see requests).
- "Write prescription" → link to `/prescriptions?encounterId=…` (T06 must honour it).
- `LabReportBadgeListener` on `LabReportVerified` → `clinical_lab_badge` + `NotificationPort`.

### Access / ports
- `ClinicalAccess` + `DefaultClinicalAccess` (safe default): staff roles for vitals; doctors via `PatientAccessPort` or named open encounter / checked-in appointment.
- Flyway `V300`–`V302`; messages `clinical_{en,bn}`; templates under `templates/clinical/**`.
- Unit tests: boundary edges, MAP/SI, BP parse errors, max aggregation, rule-only vital, `TrendSvg` (not executed this run).
