# T12 — HL7 FHIR R4 facade: report

Status: **implemented** (compile-checked). **Tests were not run** (per agent instructions: no `mvnw verify` / test, no Docker).

## What was built

Owns: `com.mediflow.fhir/**`, Flyway `V600–V649`, `messages/fhir_{en,bn}.properties`.

### Persistence
- `V600__fhir_oauth_clients.sql` — `fhir_oauth_client`, `fhir_access_token` for OAuth2 client-credentials.

### Auth
- Dedicated `SecurityFilterChain` on `/fhir/r4/**` (CSRF off; session optional).
- `GET /fhir/r4/metadata` and `POST /fhir/r4/oauth/token` permitAll.
- Bearer tokens from client-credentials grant; patient-consented **session** still works via the main security context.
- Machine clients require active `ConsentType.FHIR_SHARE` on the patient being read.

### Mappers (HAPI FHIR R4 structures)
Patient; Organization + Location (hospital / department); Practitioner + PractitionerRole; Schedule + Slot; Appointment; Encounter (EMER class when Red Alert present) + Flag; Observation (vital-signs profile, LOINC + UCUM, BP components); Condition (ICD-10); AllergyIntolerance; MedicationRequest (RxNorm/ATC + DGDA brand extension); MedicationDispense; ServiceRequest (**DIRECT** → requester = Patient); DiagnosticReport; Consent; AuditEvent + Provenance; Communication (Notification) + Task (Reminder).

### REST
- `GET /fhir/r4/{Type}/{id}` — JSON (`application/fhir+json`)
- `GET /fhir/r4/Patient/{id}/$everything` — IPS-style searchset Bundle
- `GET /fhir/r4/metadata` — CapabilityStatement
- Every successful/denied clinical read audited via `AuditPort` (`FHIR_READ` / `FHIR_READ_DENIED`)
- RBAC via `FhirAccessGuard` + `PatientAccessPort` (doctors/ER assignment; patients own record; admin all)

### Validation & tests (written, not executed)
- `R4ResourceValidator` — encode/parse round-trip + HAPI base validator
- `FhirResourceMapperTest` — round-trip per key resource; assert validator errors empty
- `FhirAccessIT` — metadata public; unauthenticated blocked; doctor without assignment 403; admin/patient OK; client-credentials gated on FHIR_SHARE

## Deviations
- Full HAPI **profile** InstanceValidator not on classpath (only `hapi-fhir-structures-r4`). Requested validation jars in `docs/plan/requests/T12.md`. Structural/round-trip checks stand in until then.
- FHIR base URL hard-coded (`FhirSystems.FHIR_BASE`); optional property requested.
- Location / Schedule / Provenance use synthetic id prefixes (`hospital-`, `dept-`, `schedule-`, `prov-`) because MediFlow has no separate tables for those FHIR types.
- No Thymeleaf UI (read-only JSON facade only).
- Cross-module: does **not** inject other modules’ services; reads shared tables via `FhirDataStore` (`EntityManager`) + shared ports only.
