# T01: requests to other modules

T01 did not edit `shared/`, `pom.xml`, `application*.yml`, layout templates or V1. These changes are needed or recommended elsewhere.

## T00 (foundation)
1. **Argon2 (required for the spec).** Add `org.bouncycastle:bcprov-jdk18on` to `pom.xml`. Then either:
   - make `SecurityConfig.passwordEncoder()` an Argon2-default `DelegatingPasswordEncoder` (`{argon2}` new, `{bcrypt}` legacy accepted), or
   - expose `com.mediflow.identity.password.PasswordHasher` as the `PasswordEncoder` bean.

   Without BouncyCastle, `PasswordHasher` falls back to BCrypt (cost 12) and logs a warning.
2. **Login page (`templates/login.html`):**
   - add a "Forgot password?" link to `/identity/password/forgot`;
   - show a success message for `param.reset`. The keys `identity.password.reset.done` and `identity.password.forgot.link` exist in `messages/identity_*`.
   - A locked account currently shows the generic `?error` message. That is acceptable (no enumeration), but an optional hint "too many attempts, try again in 15 minutes" could be shown.
3. **`ConsentType.REFERRAL_SHARE`:** add this enum value. Until then, referral-share consent is stored as `DATA_PROCESSING` with `version_label = 'REFERRAL_SHARE/v1'`, and `ConsentService.hasActiveConsent` excludes those rows.
4. **`application-dev.yml`:** set `mediflow.identity.mfa.enforce: false` explicitly, and leave it unset (default true) for prod. Today the default is "on unless the `dev` profile is active", which keeps `LoginAndNavigationIT` green.
5. **Authentication provider (optional):** `IdentityAuthenticationProvider` (the lockout-aware `DaoAuthenticationProvider`) is a plain `@Component`, which Spring Security picks up as the only `AuthenticationProvider` bean. If `SecurityConfig` ever declares its own provider or `AuthenticationManager`, wire this one explicitly.
6. **CSRF cookie (optional hardening):** `CookieCsrfTokenRepository.withHttpOnlyFalse()` is fine for forms. Consider `SameSite=Strict` on the XSRF cookie too.

## T04 (red alert / ER)
- `red_alert` has no assignee column. As a result, `PatientAccessPort.isAssigned` treats **any** ER user as assigned to a patient with an active red alert (`handover_status IS NULL`). If per-ER assignment is wanted, add an `assigned_er_user_id` column to `red_alert` and tell T01 (a one-line change in `JdbcAccessFacts.activeRedAlert`).

## T09 (notifications)
- `BreakGlassService` calls `NotificationPort.notifyUser(adminId, "IN_APP" | "EMAIL", subject, body)` for every enabled admin.
- `PasswordResetService` sends the reset link through the `EMAIL` channel. The body contains a single-use URL, so do not log bodies.

## T11 (admin console / patient portal)
- Admin menu links:
  - `/identity/break-glass/review` (break-glass review list, ADMIN);
  - `/identity/sharing?patientId=` (referral shares).
- Staff management UI: call `StaffUserService` (signatures in `reports/T01.md`). It is ADMIN-only through `@PreAuthorize`.
- "Who accessed my record" is T11's. T01 writes `BREAK_GLASS_ACTIVATED` / `BREAK_GLASS_REVIEWED` / `REFERRAL_SHARE_*` / `LOGIN_*` / `MFA_*` audit events through `AuditPort`.

## T02 / T03 / T05 / T06 / T07 (clinical modules)
- Guard controllers and services with:
  - `@PreAuthorize("@access.canReadPatient(#patientId)")`;
  - `canWritePatient`, `canReadLabOrder(#labOrderId)`, `canReadPrescription(#rxId)`;
  - `@access.can('LAB_ORDERS','C',#patientId)`.
- On "not assigned" pages, link doctor and ER users to `/identity/break-glass/new?patientId={id}&continue={currentPath}`.
- **T06:** call `MfaReauthService.requireFreshMfa()` before signing. It throws `MfaStepUpRequiredException`, which `MfaWebAdvice` turns into a redirect to `/identity/mfa/step-up?continue=<referer>`; `/api/**` gets 401.
- **T02:** at patient registration, call `ConsentService.recordConsent(patientId, userId, ConsentType.DATA_PROCESSING, true, "<policy version>")`.
