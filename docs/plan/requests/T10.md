# T10 requests (Notifications & reminders, M8)

## R1. Notification bell in the navbar (layout owner, T00)
Put the bell into `templates/layout/base.html` `nav`, inside `<div class="d-flex align-items-center gap-2">`, before the EN/বাংলা buttons:

```html
<th:block th:replace="~{notification/fragments :: bell}"></th:block>
```

The fragment renders only for authenticated users. It calls `@notificationInbox.unreadCount()` and links to `/notifications`. The icon is an inline SVG, so no extra CSS or JS is needed and it is CSP-safe.

## R2. Adherence widget on the patient dashboard (T02)
```html
<div th:replace="~{notification/fragments :: adherence}"></div>
```
It shows adherence % for the signed-in patient (taken ÷ doses due) and links to `/notifications/reminders`. For staff views of a patient, call `@notificationAdherence.percentFor(patientId)`. It returns `Integer`, or null when no dose is due yet.

## R3. Missing domain events (T00 `DomainEvents` plus the owning modules)
CONVENTIONS asks for these, but they do not exist in `DomainEvents`, so T10 has no listener for them yet. The templates already exist (`QUEUE_NEXT`, `SCHEDULE_CHANGED`, `FOLLOW_UP_REMINDER`).
- `QueueCalled(appointmentId, patientId, String tokenNo, Instant at)` or a "you're next" event, published by T04 (queue). It would trigger the `QUEUE_NEXT` message.
- `ScheduleChanged(appointmentId, patientId, Instant newStart, Instant at)` (or `AppointmentRescheduled`), published by T03/T04. It would re-send to patient and doctor and re-plan the 24h/2h reminders through `ReminderService.scheduleForAppointment`, which already cancels old ones for the same source.
- `FollowUpScheduled(sourceId, patientId, LocalDate date, Instant at)`, published by T05/T06 when a follow-up date is set. It would call `ReminderService.scheduleFollowUp`. The method is public, so a module may also call it directly.

## R4. Optional config (application*.yml owner)
These defaults are in code. Only override them per environment:
```yaml
mediflow:
  notification:
    transport: auto            # auto | sync | rabbit
    max-attempts: 3
    initial-backoff: 2s
    backoff-multiplier: 2.0
    max-backoff: 5m
    mail-from: no-reply@mediflow.local
    sms:  { provider: log }    # prod: http + url, sender-id; key via MEDIFLOW_NOTIFICATION_SMS_APIKEY
    push: { provider: log }    # prod: fcm + project-id; token via MEDIFLOW_NOTIFICATION_PUSH_ACCESSTOKEN
    scheduler: { enabled: true, batch-size: 200 }
  # mediflow.notification.scheduler.interval-ms (default 60000) controls the reminder job
```

## R5. Nav link to the staff call list (layout owner)
Optionally add a link for `hasAnyRole('FRONT_DESK','NURSE','ER','ADMIN')` to `/notifications/call-list` (key `notification.nav.callList`). The page is also reachable from the inbox's tabs.
