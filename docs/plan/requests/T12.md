# T12 requests (outside Owns paths)

## Dependencies (`backend/pom.xml`) — HAPI profile validator

Please add (versions aligned with existing `${hapi.fhir.version}` = 7.6.1):

```xml
<dependency>
  <groupId>ca.uhn.hapi.fhir</groupId>
  <artifactId>hapi-fhir-validation</artifactId>
  <version>${hapi.fhir.version}</version>
  <scope>test</scope>
</dependency>
<dependency>
  <groupId>ca.uhn.hapi.fhir</groupId>
  <artifactId>hapi-fhir-validation-resources-r4</artifactId>
  <version>${hapi.fhir.version}</version>
  <scope>test</scope>
</dependency>
```

T12 ships `R4ResourceValidator` that round-trips JSON and runs HAPI’s base `FhirValidator`. Full R4 **profile** validation (vital-signs StructureDefinition, etc.) needs the InstanceValidator + validation-resources jars above. Until then, unit tests assert zero structural/round-trip errors.

## Optional config (`application.yml` / env)

- `mediflow.fhir.base-url` (default `http://localhost/fhir/r4`) for CapabilityStatement `implementation.url` and absolute fullUrls in `$everything`. Currently hard-coded in `FhirSystems.FHIR_BASE`.

## No shared-port changes required

Fhir module uses `AuditPort`, `PatientAccessPort`, `ClockPort`, and shared domain/repos via `EntityManager` only.
